# 9. Production Roadmap

## Главный принцип

**КАЧЕСТВО > РАЗМЕР.** Не строить остров целиком, пока не работает один
регион. Порядок такой: сначала закрыть технические риски на прототипах,
затем сделать вертикальный срез в финальном качестве, и только потом
строить остальное — копируя уже проверенный рецепт.

## Технический план (Unity)

> Версии пакетов и имена API в Unity меняются от релиза к релизу. Всё ниже —
> отправная точка: перед началом проверь в Package Manager своего проекта,
> какие версии реально стоят, и сверяйся с документацией именно этой версии.

### Движок и рендер

- **Unity 6 (LTS-ветка), HDRP.** Для этой игры HDRP даёт из коробки то, на
  чём держится её картинка: объёмный туман, объёмные облака, физическое
  небо, систему воды (появилась в HDRP 2022.2, доступна в Unity 6),
  качественный дождь и мокрые поверхности.
- **Когда выбрать URP:** если целевое железо — ноутбуки, Steam Deck или
  мобильные устройства. Тогда объёмные эффекты придётся делать вручную, и
  стиль картинки надо упростить заранее, а не в конце.
- Решение принимается в пре-продакшене один раз. Переезд между HDRP и URP
  посреди проекта — это переделка всех материалов и освещения.

### Пакеты

| Задача | Пакет | Примечание |
|---|---|---|
| Камеры, кат-сцены | **Cinemachine 3.x** + **Timeline** | В Cinemachine 3 основной компонент называется `CinemachineCamera` (в 2.x был `CinemachineVirtualCamera`) — не путай туториалы разных версий |
| Навигация динозавров | **AI Navigation** (`NavMeshSurface`) | Отдельный тип агента под каждый размер: мелкий, средний, крупный, T-Rex, брахиозавр |
| IK лап, взгляд | **Animation Rigging** | Two Bone IK для лап, Multi-Aim для головы |
| Потоковая загрузка регионов | **Addressables** + аддитивные сцены | Сцена-загрузчик + постоянная сцена систем + сцены регионов |
| Ввод | **Input System** | Геймпад как основной контроллер: вибрация = инфразвук T-Rex |
| Растительность | Terrain + GPU instancing; **GPU Resident Drawer** в Unity 6 | Проверь, работает ли GPU Resident Drawer с твоей версией HDRP и выбранными шейдерами растительности |
| VFX | **Visual Effect Graph** | Дождь, пепел, колония птеранодонов вдали, брызги воды |
| Аудио | **FMOD** или **Wwise** (сторонние) | Динамическая музыка по слоям, окклюзия, снапшоты «снаружи/в кабине» |

### Архитектура сцен

```
Bootstrap.unity            ← загрузка, настройки, переход в меню
Persistent.unity           ← всегда загружена: игрок, камера, UI, аудио,
                             экосистема (L2-симуляция), сохранения, время, погода
Region_00_Base.unity       ← аддитивно
Region_Flight.unity        ← аддитивно; пока идёт полёт, грузится Region_01
Region_01_Valley.unity     ← аддитивно
Region_02_Jungle.unity ...
```

- **Полёт — это загрузочный коридор.** Пока игрок 4 минуты сидит в салоне,
  в фоне выгружается база и грузится долина. Поэтому загрузочного экрана
  нет, и это решение одновременно дизайнерское и техническое.
- Между регионами загрузка прячется в «горлышках» из
  [карты](04-island-map.md#переходы-и-потоковая-загрузка).
- **Данные — в ScriptableObject:** виды (восприятие, потребности, журнал),
  образцы, цели, диалоги, погода. Геймдизайнер балансирует без
  программиста.

### Системы и их порядок

| Система | Зависит от | Когда |
|---|---|---|
| Контроллер игрока (3-е лицо, красться, лазание) | Input System | Пре-продакшен |
| Камера игрока и бленды в кат-сцены | Cinemachine | Пре-продакшен |
| Контейнер ДНК (конечный автомат состояний) | — | Пре-продакшен |
| Восприятие (зрение, слух, запах) | Контроллер игрока | Вертикальный срез |
| Utility AI + LOD ИИ | Восприятие, навигация | Вертикальный срез |
| Стадо (агент-стадо → особи) | Utility AI | Вертикальный срез |
| Следы и сканер | — | Вертикальный срез |
| Журнал и камера | Следы | Вертикальный срез |
| Сохранения | Всё выше | Вертикальный срез (базово) |
| Время суток, погода | — | Core systems |
| Распределение питания | — | Core systems (Акт III) |
| Режиссёр экосистемы | Utility AI, погода | Core systems |
| Лагерь и улучшения | Сохранения | Core systems |
| Вода: чтение, лодка, всплытия | HDRP Water | Контент A (Акт IV) |
| Ветер и запах | Восприятие, погода | Контент B (Акт VII), прототип раньше |

## Бюджеты производительности

**Цель:** 60 fps (16,6 мс на кадр). Целевое железо фиксируется в
пре-продакшене и проверяется на реальной машине, а не на машине
разработчика. Пока его нет, ориентир — видеокарта уровня RTX 3060 в 1080p.

| Бюджет CPU (главный поток) | мс |
|---|---|
| Игровая логика и ИИ (L0 + L1) | 2,0 |
| Анимация и IK | 2,5 |
| Физика | 1,0 |
| Аудио | 0,5 |
| Потоковая загрузка | 0,5 |
| Подготовка рендера | 6,0 |
| Запас | 4,1 |

| Лимит сцены | Значение |
|---|---|
| Динозавры на L0 | ≤ 12 |
| Динозавры на L1 | ≤ 40 |
| Стада на дальнем плане | Импостеры, 1 draw call на стадо |
| Источники света с тенями в кадре | ≤ 4 (+ солнце) |
| Объёмный туман | Качество «Medium» по умолчанию, «High» только в кат-сценах |

Что можно не делать ради производительности:

- Растения дальше 60 м не реагируют на игрока — игрок этого не видит.
- Мелкие декали следов исчезают дальше 25 м.
- Отражения воды в реальном времени — только у реки и в кат-сценах. На
  болоте хватает probe-отражений под туманом.
- Освещение базы, K-4 и Объекта-0 — запечённое, с динамическими источниками
  только там, где свет двигается по сюжету (красный свет K-4, молнии).

Как искать узкие места — по методу из
[performance-profiling-method](../../skills/core/performance/performance-profiling-method/SKILL.md):
сначала измерить, потом менять.

## Фазы

Сроки даны для небольшой команды из 4–6 человек: программист геймплея,
программист ИИ, художник окружения, художник персонажей и существ,
аниматор, дизайнер-сценарист. Для соло-разработчика — отдельный план ниже.

### Фаза 0 — Пре-продакшен (6 недель)

**Цель:** закрыть три главных технических риска **до** того, как делать
красивое.

1. **Стадо и LOD ИИ.** 30 капсул-трицератопсов пасутся, пьют, пугаются
   игрока и переходят между L0, L1 и L2 без рывков. Проверка: профайлер,
   ИИ < 2 мс.
2. **Цикл ДНК.** Мазок → контейнер → анализ → `VERIFIED` / `REJECTED`, кейс
   на рюкзаке с огоньками. Проверка: новичок понимает правило живых клеток с
   первой попытки на туше.
3. **Полёт как загрузка.** Салон вертолёта, 4 минуты, за это время выгружается
   база и грузится долина без просадок ниже 55 fps.

**Плюс:** арт-библия (палитры регионов, силуэты видов), аудио-направление (3
референса на регион), пайплайн Blender → Unity (масштаб, имена, LOD),
документ контроля версий.

**Готово, когда:** все три прототипа работают на целевом железе.

### Фаза 1 — Вертикальный срез (4 месяца)

**Содержание:** всё из [первых 30 минут](07-first-30-minutes.md) + ДНК 1 в
почти финальном качестве:

- база «Порог» (11 помещений);
- CS01–CS09;
- вертолёт снаружи и внутри;
- Долина высадки;
- трицератопсы, брахиозавр, паразауролофы, компсогнаты;
- следы, сканер, журнал, камера;
- восприятие (зрение и слух).

**Готово, когда:** метрики плейтеста из
[файла 7](07-first-30-minutes.md#что-проверять-на-плейтестах) выполнены на 8–12
игроках, которые не видели игру раньше. Если нет — итерации в этой фазе, а не
переход дальше.

### Фаза 2 — Основные системы и Акт III (3 месяца)

Время суток, погода, запах (прототип), режиссёр экосистемы, лагерь, рапторы
и стайный ИИ, распределение питания. Джунгли и комплекс K-4 от грейбокса до
финала.

**Готово, когда:** глава рапторов пугает. Проверка — тот же плейтест: больше
половины игроков описывают её словами «страшно», «напряжённо».

### Фаза 3 — Контент A: Акты IV–V (4 месяца)

Болото, река, спинозавр и вода, атака на лагерь, горы, колония. Самый
дорогой по технике отрезок: симуляция воды и сотни птиц.

### Фаза 4 — Контент B: Акты VI–VIII (4 месяца)

Вулкан, пещеры, ЕВА-0, лагерь D-04, территория T-Rex, Объект-0, Маяк,
финальная миграция, концовки.

### Фаза 5 — Полировка (3 месяца)

Оптимизация по бюджетам, сведение звука, доступность, локализация (RU, EN),
QA-проходы, балансировка стелса, сокращение кат-сцен по данным плейтестов.

**Итого:** около 22 месяцев для команды из 4–6 человек.

## Если ты делаешь игру один

Полная игра в одиночку — это 5+ лет. Реалистичный путь другой:

1. **Месяцы 1–2:** Фаза 0 целиком. Капсулы вместо динозавров, кубы вместо
   базы.
2. **Месяцы 3–8:** вертикальный срез. Динозавры и персонажи — из Asset Store
   с готовыми анимациями. Свои модели — только кейс, контейнеры и вертолёт:
   это «лицо» игры.
3. **После среза** — показать его людям. Срез — это то, с чем ищут
   команду, издателя или грант. По его результату решается, делать ли
   остальное и в каком объёме.

## Лестница урезания

Если сроки горят, резать сверху вниз. Верхние пункты стоят дорого, а игрок
почти не заметит их отсутствия.

| # | Что урезать | Экономия | Что теряем |
|---|---|---|---|
| 1 | Пахицефалозавр и анкилозавр | 2 существа | Разнообразие фона |
| 2 | Дрон | Система | Ничего сюжетного |
| 3 | Улучшения лагеря → 2 модуля | Система и ассеты | Часть прогрессии |
| 4 | Болото сливается с рекой в один регион | Регион | Контраст эмоций в Акте IV |
| 5 | Концовки: «Вуаль» + «Рассвет» + «Пепел» | Одна концовка | Вариативность |
| 6 | Возвращение на остров после титров | Логика мира | Реиграбельность |

Что **не режется никогда**: вид острова (CS06), правило живых клеток, пять
разных способов взять ДНК, «стакан воды», первый рассвет над островом.

## Риски

| Риск | Вероятность | Что делать |
|---|---|---|
| Анимация динозавров дороже, чем кажется | Высокая | Бюджет анимаций на вид зафиксирован в [списке моделей](08-asset-list.md); сначала купленные заглушки |
| ИИ экосистемы разрастается | Высокая | Жёсткие лимиты L0 и L1; якорные особи отдельно от популяции |
| Вода для спинозавра | Средняя | Прототип всплытия — в конце Фазы 0: если HDRP Water не тянет, всплытие делается мешем и VFX в кат-сцене |
| Растительность съедает GPU | Средняя | Бюджет плотности на регион, проверка на целевом железе каждый спринт |
| Сюжет расходится между файлами | Средняя | [Сюжет](03-story.md) — единственный источник правды о лоре; изменения — только через него |
| Название UMBRA | Средняя | Проверить доступность товарного знака до публичного анонса. Для разработчиков Unity есть ещё одна деталь: Umbra — имя технологии окклюзии внутри Unity, и это засоряет поиск документации |

## Первые две недели — конкретно

1. Создать проект Unity 6 на шаблоне HDRP. Сразу подключить Git с LFS для
   бинарных файлов.
2. Тест масштаба: куб 1×1×1 м из Blender рядом с капсулой высотой 1,8 м.
3. Персонаж от третьего лица (можно начать со Starter Assets) и камера
   Cinemachine за плечом.
4. Грейбокс базы «Порог» из ProBuilder: 11 комнат по [карте базы](07-first-30-minutes.md#карта-базы-порог).
   Пройти её за 7 минут.
5. `ScriptableObject` вида (`SpeciesData`) и контейнера (`DnaContainer` со
   состояниями EMPTY → VERIFIED/REJECTED).
6. Туша и кровь в грейбокс-долине: взять образец с туши → `REJECTED`, с крови
   → `VERIFIED`. Огонёк на рюкзаке.
7. 10 капсул-трицератопсов на NavMesh: пасутся, пугаются игрока, убегают.

После этих семи пунктов уже можно играть в 3 минуты будущей игры. Всё
остальное наращивается на этот каркас.
