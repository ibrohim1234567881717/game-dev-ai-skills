# Задание: озвучка UMBRA через Qwen3-TTS

Файл для ИИ-агента, который работает на компьютере автора игры (Windows). Задача — озвучить все реплики игры, собрать игру со звуком, проверить результат и отправить его в репозиторий. Всё нужное для этого уже написано; тебе остаётся установить модель 1.7B, сгенерировать звук и проверить его.

## Коротко

- **Qwen3-TTS 0.6B уже скачана** на этом компьютере. Найди её (раздел 3.1). Другую 0.6B не качай.
- **Qwen3-TTS 1.7B нужно установить самостоятельно** (раздел 3.2).
- **Главные персонажи и кат-сцены — 1.7B. Черновая озвучка и второстепенные — 0.6B.** Распределение по персонажам — в разделе 4.
- **Один персонаж — одна модель.** Если у Лены часть реплик будет от 0.6B, а часть от 1.7B, она заговорит двумя разными голосами.
- Реплик для озвучки: **222**, из них **63** звучат в кат-сценах. Все реплики с голосом каждого персонажа — в разделах 6 и 7.
- Тексты реплик в коде игры **не меняй** (раздел 1, почему). Произношение правится через `voices.json`.
- Готовые удачные клипы **не перезаписывай**. `--force` — только осознанно, для конкретных персонажей или id.

## 1. Проект и как игра находит звук

Репозиторий: `https://github.com/ibrohim1234567881717/game-dev-ai-skills`, ветка `claude/awesome-noether-anq584`.

```
cd %USERPROFILE%\Desktop
git clone -b claude/awesome-noether-anq584 https://github.com/ibrohim1234567881717/game-dev-ai-skills.git
cd game-dev-ai-skills
```

Если репозиторий уже склонирован, в нём выполни `git checkout claude/awesome-noether-anq584` и `git pull`. Все команды ниже запускаются из корня репозитория.

| Файл | Что это |
|---|---|
| [extract_lines.py](extract_lines.py) | Собирает реплики из `web/src/*.js` в `lines.json` |
| [lines.json](lines.json) | Список реплик: `id`, персонаж, текст для синтеза (`say`), эмоция, рация, файл:строка |
| [voices.json](voices.json) | Голоса персонажей, эмоции, произношение, правки отдельных реплик |
| [generate.py](generate.py) | Синтез: пишет `voice/audio/<персонаж>/<id>.mp3` и `voice/audio/manifest.json` |
| [../build.py](../build.py) | Сборка игры `web/dist/umbra.html`; встраивает звук из `voice/audio` |
| [README.md](README.md) | Подробная инструкция к пайплайну и разбор неполадок |

Как игра находит клип: `id` реплики — это хеш FNV-1a от строки «персонаж|исходный текст». Поэтому:

- Если поменять текст реплики в коде или в `lines.json`, у неё изменится `id`, и игра перестанет находить звук. **Не редактируй тексты.**
- Ударение, латиница, цифры читаются неправильно? Добавь замену в `voices.json` → `pronounce` (например, `"D-04": "Дэ-ноль-четыре"`) или правку одной реплики в `line_overrides`: `"<id>": {"say": "…"}`. Потом запусти `extract_lines.py` заново. `id` при этом не меняется: меняется только то, что произносит модель.
- Реплики по рации, интеркому и из записей генерируй **чистым голосом**: игра сама накладывает радиофильтр (в таблицах они отмечены «рация»).
- Системные подписи (`[Сканер]`, `[Улика 3/8]`, `[Жетон]` и т. п.), повествование в кадре и реплики с подстановкой чисел не озвучиваются. Это задумано: `extract_lines.py` пропускает их сам.

## 2. Окружение

Нужен Python **3.10–3.12**. На 3.9 пакет `qwen-tts` не импортируется, 3.13 он не поддерживает. Проверь: `python --version` (или `py -0`, чтобы увидеть все установленные версии).

Виртуальное окружение создавай **в папке `.venv` в корне репозитория**: она уже в `.gitignore`, и её не отправят в git.

```
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
nvidia-smi
```

PyTorch ставится **до** `qwen-tts`, иначе pip поставит версию только для процессора:

- есть видеокарта NVIDIA (`nvidia-smi` её показал): `pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu126` (номер `cu…` сверь на pytorch.org, раздел Get Started);
- нет видеокарты: `pip install torch torchaudio` (генерация будет в разы медленнее).

```
pip install -U qwen-tts soundfile "huggingface_hub[cli]"
python -c "import torch; print(torch.__version__, 'CUDA:', torch.cuda.is_available())"
```

Неполадки (`torchaudio`, SoX, MP3, нехватка видеопамяти) разобраны в [README.md](README.md#неполадки).

## 3. Модели

### 3.1. Qwen3-TTS 0.6B — уже есть на компьютере

`generate.py` ищет модель сам: в кеше Hugging Face (`%USERPROFILE%\.cache\huggingface\hub\models--Qwen--Qwen3-TTS-12Hz-0.6B-…`), в кеше ModelScope, в Загрузках, на Рабочем столе, в Документах, в `C:\models`. Проверка:

```
python games\expedition-d05\web\voice\generate.py --dry-run --limit 10
```

Скрипт напечатает, какую модель взял. Если не нашёл — поищи папку и передай её через `--model`:

```
powershell -c "Get-ChildItem -Path C:\,D:\ -Recurse -Directory -Filter *Qwen3-TTS* -ErrorAction SilentlyContinue | Select FullName"
```

В папке модели должны быть `config.json` и подпапка `speech_tokenizer\`. Посмотри, какая это разновидность:

- **0.6B-CustomVoice** — 9 готовых голосов, черновик можно делать сразу.
- **0.6B-Base** — клонирует голос по образцу. Ей нужны образцы `voice\refs\<персонаж>.wav`; их создаёт модель 1.7B (`--ref-model`, шаг 5). В этом случае черновой проход делай после установки 1.7B.

Эмоциями 0.6B не управляет: пакет `qwen-tts` сам отбрасывает инструкции для 0.6B. Различие голосов на 0.6B держится на выборе голоса, высоте (`pitch_semitones`) и темпе (`speed`) из `voices.json`.

### 3.2. Qwen3-TTS 1.7B — установить самостоятельно

Существуют три разновидности 1.7B. Для этой игры скачай первые две; третью — только если выберешь вариант C на шаге 5.

| Модель | Что умеет | Риск |
|---|---|---|
| `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice` | 9 готовых голосов + эмоции и стиль по текстовой инструкции | Готовые голоса — носители китайского, английского, японского и корейского; русский может быть с акцентом |
| `Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign` | Голос строится по описанию персонажа (`description` в `voices.json`) + эмоции | Каждая реплика синтезируется заново, тембр между репликами может «гулять» |
| `Qwen/Qwen3-TTS-12Hz-1.7B-Base` | Клонирует голос по образцу 10–20 с | Эмоций по инструкции нет |

```
hf download Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice --local-dir C:\models\Qwen3-TTS-12Hz-1.7B-CustomVoice
hf download Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign --local-dir C:\models\Qwen3-TTS-12Hz-1.7B-VoiceDesign
```

- В старых версиях `huggingface_hub` команда называется `huggingface-cli download` с теми же аргументами.
- Если Hugging Face недоступен или очень медленный, модели есть на ModelScope: `pip install modelscope`, затем `modelscope download --model Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice --local_dir C:\models\Qwen3-TTS-12Hz-1.7B-CustomVoice`. Имя команды проверь по `modelscope --help`, я его не запускал.
- Каждая модель весит несколько гигабайт, 1.7B заметно медленнее 0.6B. Если не хватает видеопамяти, добавь к `generate.py` ключ `--dtype fp16`, а в крайнем случае `--device cpu`.
- После загрузки проверь, что в папке есть `config.json` и `speech_tokenizer\`.

## 4. Кто какой моделью

Правило автора: главные персонажи и кат-сцены — 1.7B, черновая озвучка и массовые NPC — 0.6B. В игре почти нет «массовых» NPC: почти у каждого второстепенного персонажа есть реплика в кат-сцене. Поскольку один персонаж должен звучать одной моделью, распределение такое:

| Персонаж | Ключ | Реплик | В кат-сценах | Итоговая модель | Почему |
|---|---|---|---|---|---|
| Лена Арден | `lena` | 97 | 16 | **1.7B** | главная героиня рядом с игроком всю игру, 97 реплик, самый широкий диапазон: восторг, шёпот, крик по рации, слёзы |
| Виктор Хальм | `halm` | 50 | 22 | **1.7B** | главный персонаж и скрытый антагонист, 22 реплики в кат-сценах, брифинг и финал на Маяке держатся на его голосе |
| Диего Рамос | `diego` | 25 | 7 | **1.7B** | главный напарник, крик в ночной атаке, раненый голос в пещере |
| Лукас Ортис | `lucas` | 20 | 7 | **1.7B** | главный напарник, пилот: шутки и напряжение в полёте сквозь Вуаль |
| Итан Рид | `ethan` | 9 | 1 | **1.7B** | герой игрока; реплик мало, но они ключевые (догадки, «Диего!») |
| Элиас Варн | `varn` | 4 | 4 | **1.7B** | все 4 реплики в кат-сцене Ковчега, это главный монолог игры |
| Мара Линд | `mara` | 3 | 0 | **1.7B** | мать Лены, аудиодневник — самые эмоциональные реплики сюжета |
| Ада Кесслер | `kessler` | 1 | 1 | **1.7B** | единственная реплика звучит в кат-сцене финала |
| Нора Квист | `nora` | 9 | 3 | **1.7B** | 3 из 9 реплик в кат-сценах (взлёт, Вуаль); допускается 0.6B, см. ниже |
| Юсуф | `yusuf` | 3 | 2 | **1.7B** | 2 из 3 реплик в кат-сцене с кейсом; допускается 0.6B, см. ниже |
| Пилот D-02 | `d02pilot` | 1 | 0 | **0.6B** | одна реплика с бортового самописца, звучит через радиофильтр, вне кат-сцены |

- **0.6B** делает черновик всех реплик (шаг 2): так быстрее проверить весь конвейер, тайминги и то, что игра находит каждый клип. Потом 1.7B заменяет черновик у персонажей, отмеченных 1.7B.
- **Допустимое упрощение.** Если 1.7B работает слишком медленно, у `nora` и `yusuf` можно оставить 0.6B. Нору в игре всегда слышно через радиофильтр, у Юсуфа всего 3 реплики. Главным персонажам, Варну, Маре и Кесслер оставь 1.7B обязательно.
- **Если автор захочет делить строго по репликам, а не по персонажам**, в конце файла есть список id всех реплик из кат-сцен. Их можно передать в `--only` через запятую. Предупреди автора, что тогда голос одного персонажа в кат-сцене и в игре будет разным.

## 5. Порядок работы

**Шаг 1. Обновить список реплик.**

```
python games\expedition-d05\web\voice\extract_lines.py
```

Скрипт напечатает таблицу по персонажам. Сейчас реплик 222. Если число другое, значит, после создания этого файла менялись диалоги; это нормально, продолжай. Список в разделе 7 тогда может немного отличаться от `lines.json`, и верить надо `lines.json`.

**Шаг 2. Черновик всех реплик на 0.6B.** Сначала пять реплик на пробу, потом всё:

```
python games\expedition-d05\web\voice\generate.py --model <папка 0.6B> --limit 5
python games\expedition-d05\web\voice\generate.py --model <папка 0.6B>
```

Генерацию можно прервать Ctrl+C: при следующем запуске она продолжит с того же места. Клипы появляются в `games\expedition-d05\web\voice\audio\<персонаж>\`.

**Шаг 3. Собрать игру и проверить черновик в игре.**

```
python games\expedition-d05\web\build.py
start games\expedition-d05\web\dist\umbra.html
```

Сборка печатает, сколько клипов и мегабайт встроено. В игре: «Начать экспедицию». Первая реплика — Нора по интеркому; голос должен звучать через радиофильтр. Потом подойти к Хальму у большого экрана и нажать E: брифинг должен идти голосом, а не только субтитрами. Для игры нужен интернет: движок three.js грузится с CDN.

**Шаг 4. Сохранить черновик**, прежде чем что-то перезаписывать:

```
xcopy games\expedition-d05\web\voice\audio games\expedition-d05\web\voice\audio_draft_06b /E /I
```

Эту копию в git не отправляй.

**Шаг 5. Выбрать разновидность 1.7B.** Сгенерируй по 5 реплик Лены и Хальма в каждом варианте, после каждого прогона скопируй их файлы в отдельную папку для сравнения (например, `voice\ab\A\`, `voice\ab\B\`):

```
rem A: готовые голоса + эмоции
python games\expedition-d05\web\voice\generate.py --model C:\models\Qwen3-TTS-12Hz-1.7B-CustomVoice --only lena,halm --limit 10 --force
rem B: голос по описанию + эмоции
python games\expedition-d05\web\voice\generate.py --model C:\models\Qwen3-TTS-12Hz-1.7B-VoiceDesign --only lena,halm --limit 10 --force
```

Вариант **C**: VoiceDesign один раз создаёт образец голоса `voice\refs\<персонаж>.wav`, а Base клонирует его на всех репликах. Тембр стабильный, но эмоций по инструкции нет. Для него скачай `Qwen/Qwen3-TTS-12Hz-1.7B-Base`:

```
python games\expedition-d05\web\voice\generate.py --model C:\models\Qwen3-TTS-12Hz-1.7B-Base --ref-model C:\models\Qwen3-TTS-12Hz-1.7B-VoiceDesign --only lena,halm --limit 10 --force
```

Критерии, по порядку важности:

1. Естественный русский без акцента и без ошибок в ударениях.
2. Один и тот же тембр во всех пяти репликах персонажа.
3. Слышна эмоция: шёпот тише, крик громче, неуверенность с паузами.
4. Лена и Хальм звучат как описано в разделе 6.

**Дай автору послушать пары и выбрать.** Он русскоязычный и услышит акцент лучше. Если явного победителя нет: A, когда акцента не слышно; иначе C.

**Шаг 6. Озвучить 1.7B всех персонажей из раздела 4.** `--force` здесь заменяет черновик 0.6B, это задумано:

```
python games\expedition-d05\web\voice\generate.py --model <выбранная 1.7B> --only lena,halm,diego,lucas,ethan,varn,mara,kessler,nora,yusuf --force
```

Для варианта C добавь `--ref-model <папка 1.7B-VoiceDesign>`. У пилота D-02 (`d02pilot`) остаётся черновик 0.6B.

**Шаг 7. Прослушать и переделать неудачные дубли.** В конце запуска скрипт перечисляет клипы подозрительной длины (повтор или обрыв). Послушай их и сцены из раздела 7, отмеченные «кат-сцена». Переделать одну реплику другим дублем:

```
python games\expedition-d05\web\voice\generate.py --model <та же модель> --only <id> --force --seed 2
```

Утверждённые клипы больше не трогай. `--force` применяй только к конкретным `id`.

**Шаг 8. Собрать игру со звуком** (`build.py`, как в шаге 3) и пройти пролог и начало главы I. Если сборка предупреждает, что HTML больше 15 МБ, пережми только что созданные клипы: `--mp3-level 0.5` (это синтез заново).

**Шаг 9. Отправить в репозиторий.**

```
git add games/expedition-d05/web/voice/audio games/expedition-d05/web/voice/refs games/expedition-d05/web/voice/voices.json games/expedition-d05/web/voice/lines.json
git commit -m "Voice-over: Qwen3-TTS (1.7B main cast, 0.6B draft)"
git push
```

Если папки `refs` нет (варианты A и B), убери её из `git add`. Не отправляй `.venv`, модели, `audio_draft_06b` и `ab`. Если `git push` просит доступ, не настраивай его сам: оставь коммит и скажи автору.

## 8. Чего не делать

- Не качать другую 0.6B: она уже есть.
- Не менять тексты реплик в `web/src/*.js` и в `lines.json` (игра потеряет звук, раздел 1).
- Не перезаписывать утверждённые клипы. `--force` — только для перечисленных персонажей или конкретных `id`.
- Не смешивать модели внутри одного персонажа.
- Не отправлять в git модели, `.venv` и копии черновика.
- Не менять код игры (`web/src`), кроме случая, когда без этого звук не работает. Тогда сначала опиши проблему автору.

## 9. Что написать автору в конце

1. Какая 0.6B найдена и где лежит; какие 1.7B скачаны.
2. Какой вариант 1.7B выбран (A, B или C) и почему; что сказал автор, послушав пары.
3. Сколько клипов готово у каждого персонажа и какой моделью (`generate.py --list-speakers`).
4. Какие реплики пришлось переделывать и какие всё ещё звучат плохо (id и что не так).
5. Размер собранного `dist/umbra.html` и результат проверки в игре.
6. Хеш коммита, если удалось отправить.
